# Taxi Data Analysis (出租车数据分析项目)

An end-to-end data analysis project on taxi trip data, covering data cleaning, preprocessing, exploratory data analysis (EDA), and visualization.

## 📌 项目背景
本项目为学校实训项目，基于真实的城市出租车 GPS 轨迹数据，构建了一套完整的**大数据处理流水线**。从原始 GPS 散点数据出发，经过清洗、上下车状态识别、真实路网距离计算，最终提取出有效的行程订单（OD数据），并进行多维度的时间与空间分析。

## 🛠️ 技术栈
- **大数据计算**: Hadoop (HDFS), Apache Spark (PySpark, Spark SQL)
- **核心算法**: 基于窗口函数的上下车状态标记, Haversine 球面距离计算
- **外部接口**: OSRM API (调用真实城市路网距离)
- **数据存储**: HDFS (中间结果), MySQL (最终分析结果)
- **开发环境**: Jupyter Notebook

## 📊 核心处理流程

### 1. 数据清洗 (Data Cleaning)
- **原始数据规模**: 约 160 万条 GPS 记录（字段包含：车牌、时间、经纬度、载客状态、速度）。
- **清洗规则**:
  - 剔除空值、空字符串及重复记录。
  - 过滤经纬度超出目标城市（深圳）范围的异常点位。
  - 剔除 GPS 失效（经纬度为 0）及非法车牌（VehicleNum = 0）数据。
- **清洗结果**: 保留有效轨迹数据 **1,598,902 条**，存入 HDFS。

### 2. 数据预处理 (Data Preprocessing)
- **上下车识别**: 利用 `Window` 窗口函数，按车辆分组并按时间排序，通过 `Lag` 函数比对前后时间点的 `OpenStatus`（0空载，1载客）。`0->1` 判定为上车，`1->0` 判定为下车。
- **行程订单配对**: 将上车点和下车点按时间顺序一一匹配，生成原始行程订单。
- **真实距离计算**: 
  - 使用 Haversine 公式计算球面直线距离。
  - 调用本地部署的 **OSRM API** 获取真实的车辆路网行驶距离（平均真实里程 6.48 km）。
- **异常过滤**: 剔除里程（0.1~50km）或时长（1~120分钟）异常的订单。
- **预处理结果**: 提取出有效行程订单 **7,812 条**，存入 HDFS。

### 3. 数据分析 (Data Analysis)
结合 PySpark 与可视化图表，从时间与空间两个维度进行深度挖掘：
- **空间维度**: 
  - 载客时平均速度区间分布（20-30km/h 占比最高）。
  - 乘车距离箱线图及区间分布（0-5km 短途订单占比最高）。
- **时间维度**: 
  - 分时段平均速度分析（早晚高峰速度明显下降）。
  - 分时段载客订单量统计（下午 14:00 左右与晚间为订单高峰期）。
  - 乘车时长箱线图及区间分布（中位数约 11 分钟）。
- **结果输出**: 分析汇总结果写入 MySQL 数据库 `taxi_analysis`，供前端或 BI 看板调用。

## 💡 核心结论
- 该城市出租车大部分为**短途出行**（0-5km 订单占绝对多数），平均乘车时长约为 **14.47 分钟**。
- 城市交通的**潮汐现象**明显，早晚高峰期间，出租车运行速度显著降低，提示交通拥堵对运营效率的影响。
- 引入 OSRM 真实路网距离后，相比直线距离，平均每单实际行驶里程增加了约 **1.76 km**，更真实地反映了运营成本。
